# Poke Lounge 멀티플레이 규칙

확인 기준일: 2026-08-27

상위 문서: [Poke Lounge 게임 규칙 인덱스](./index.md)

## 1. 입장

멀티플레이 입장에 필요한 사용자 입력은 두 가지다.

1. 트레이너 닉네임
2. 친구끼리 공유한 임시 비밀번호

첫 사용자는 세션을 자동 생성하고 대기실의 방장이 된다. 같은 임시 비밀번호를 입력한 다음
사용자는 같은 대기실에 자동 참가한다.

다음 항목은 요구하지 않는다.

- Google 로그인과 계정 선택
- 계정 비밀번호
- 사용자에게 보이는 방 코드
- 방 생성·참가 선택
- 초대 링크

## 2. 임시 비밀번호

임시 비밀번호는 계정 비밀번호가 아니라 같은 세션을 찾기 위한 공유 secret이다.

- 브라우저에서 NFKC 정규화와 trim을 적용한다.
- 최대 64자를 사용한다.
- SHA-256 기반 6자리 내부 세션 key를 만든다.
- 임시 비밀번호 원문은 URL, 브라우저 저장소와 API 요청에 남기지 않는다.
- 세션이 끝나면 새 임시 비밀번호를 사용한다.

## 3. 인원과 입장 제한

| 상황                               | 규칙                                                          |
| ---------------------------------- | ------------------------------------------------------------- |
| 첫 사용자                          | 혼자 대기실에 입장하며 방장이 된다.                           |
| 시작 전 참가                       | 2~6명이 같은 대기실에 참여한다.                               |
| 참가자 6명                         | 세션 정원이 찬 상태다.                                        |
| 7번째 신규 사용자                  | 접속을 거부한다.                                              |
| 정원 초과 사용자                   | 관전자나 대기열로 자동 전환하지 않는다.                       |
| 기존 사용자의 동일 identity 재접속 | 정원이 찼거나 게임이 진행 중이어도 기존 자리로 복귀한다.      |
| `waiting`에서 빈자리 발생          | 새로운 사용자가 대기실에 참가할 수 있다.                      |
| 방장 시작 뒤 신규 사용자           | 진행 중인 준비·토너먼트에는 참가할 수 없으며 접속을 거부한다. |

신규 사용자는 `waiting` 대기실에만 참가할 수 있다. 방장 시작 뒤에는 준비 중이어도 참가자 명단을
잠그며, 기존 참가자의 동일 identity 재접속만 허용한다. 준비가 참가자 부족으로 취소돼 다시
`waiting`이 되면 대기실을 다시 열고 빈자리에 신규 사용자를 받을 수 있다.

## 4. 동일 사용자 판정

동일 사용자는 닉네임이나 임시 비밀번호가 아니라 브라우저 탭에 저장된
`playerId + sessionId` 조합으로 판별한다.

| 상황                                | 판정        |
| ----------------------------------- | ----------- |
| 같은 탭에서 새로고침                | 동일 사용자 |
| 같은 탭에서 15초 안에 Socket 재연결 | 동일 사용자 |
| 다른 일반 탭                        | 신규 사용자 |
| 시크릿 탭                           | 신규 사용자 |
| 다른 브라우저·기기                  | 신규 사용자 |
| 다른 context에서 같은 닉네임 사용   | 신규 사용자 |
| 명시적으로 나간 뒤 다시 입장        | 신규 사용자 |

닉네임은 화면에 보이는 이름이며 사용자 identity가 아니다.

## 5. 연결과 나가기

- Socket 연결이 끊기면 참가자 자리를 15초 동안 유지한다.
- 같은 identity가 15초 안에 재연결하면 기존 자리를 복구한다.
- 유예 시간 안에 재연결하지 않으면 참가자 자리를 제거한다.
- 명시적으로 나가면 identity를 지우고 입장 화면으로 돌아간다.
- 방장의 연결이 끊겨도 15초 유예 동안에는 방장 권한을 다른 참가자에게 넘기지 않는다.
- 대기실에서 방장이 명시적으로 나가거나 유예 만료로 제거되면 다음 최초 입장자가 방장이 된다.
- shared world에서 한 사용자가 나가도 2명 이상이 남으면 다른 사용자는 계속 플레이한다.
- 진행 중인 경쟁 매치에서 나가 경기 지속 조건을 잃으면 `forfeit`로 처리할 수 있다.

## 6. 공유 상태

같은 세션 사용자에게 공유하는 값은 다음과 같다.

- 서버가 승인한 닉네임
- 현재 월드 위치
- 바라보는 방향
- 방장, 준비, 참가·나가기와 연결 상태
- 챔피언십 참가자·대진·매치 결과·라운드 점수·누적 순위

## 7. 개인 상태

다음 값은 각 사용자의 개인 진행으로 유지한다.

- 파티와 PC 박스
- 포켓몬 HP, PP, 상태와 기술
- 돈과 인벤토리
- 야생 조우와 포획
- 개인 전투와 성장 보상

한 사용자가 야생전에 들어가도 다른 사용자는 월드에서 계속 움직일 수 있다.

챔피언십에서는 준비 종료 시점의 파티 복사본만 frozen party로 서버가 관리한다. 경쟁 매치에서
발생한 피해와 PP 소비는 개인 월드 파티에 반영하지 않는다.

## 8. 대기실과 챔피언십

멀티플레이 세션은 shared world의 접속 단위다. 챔피언십은 같은 세션 참가자가 3라운드 동안
경쟁하는 게임 진행 단위다.

`waiting`에서는 월드 이동과 상호작용을 막고 대기실을 표시한다. 각 참가자의 현재 파티는
서버에 자동 동기화하지만 ready는 사용자가 직접 선택한다.

방장은 현재 대기실 참가자를 입장 시각과 player ID 순서로 정렬했을 때 첫 번째 사용자다.
방장 시작은 다음 조건을 모두 만족해야 한다.

1. 참가자가 2~6명이다.
2. 모든 참가자의 Socket 연결과 presence 승인이 끝났다.
3. 모든 참가자의 현재 파티가 서버에 동기화됐다.
4. 모든 참가자가 ready를 선택했다.

ready만으로 준비 타이머를 자동 시작하지 않는다. 방장이 시작하면 서버가 그 시각을 기준으로
1라운드 준비 종료 시각을 정확히 3분 뒤로 정하고 모든 참가자에게 같은 상태를 전파한다. 이후
신규 사용자는 참가할 수 없고 기존 참가자의 재접속만 허용한다.

준비 중 참가자가 나가 2명 미만이 되면 대진을 만들지 않고 `waiting`으로 돌아간다. 이때 남은
참가자의 ready를 해제하고 대기실을 다시 열며, 전원이 다시 준비한 뒤 방장이 현재 라운드의 새
3분 준비를 시작한다. 정상적으로 1·2라운드가 끝났고 참가자가 2명 이상이면 다음 라운드의 3분
준비는 별도 ready 없이 자동 시작한다.

화면에는 현재 게임 라운드와 준비 종료까지 남은 시간을 표시한다. 이후의
3라운드·준비 3분·토너먼트·남은 체력 비율 점수·최종 우승 규칙은
[3라운드 챔피언십](./three-round-championship.md)에 고정돼 있다.
