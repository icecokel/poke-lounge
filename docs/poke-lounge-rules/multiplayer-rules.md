# Poke Lounge 멀티플레이 규칙

확인 기준일: 2026-09-03

상위 문서: [Poke Lounge 게임 규칙 인덱스](./index.md)

## 1. 입장

첫 화면은 방 만들기 화면이다. 혼자 플레이 진입은 제공하지 않는다. 사용자는 다음 값을 입력한다.

1. 트레이너 닉네임
2. 방 공개 범위
3. 친구끼리 공유한 임시 비밀번호

공개 범위는 `공개`와 `비공개` 중 선택하는 구조이며, 현재 `공개`는 비활성화하고 `비공개`만
선택할 수 있다.

첫 사용자는 세션을 자동 생성하고 대기실의 방장이 된다. 같은 임시 비밀번호를 입력한 다음
사용자는 같은 대기실에 자동 참가한다.

다음 항목은 요구하지 않는다.

- Google 로그인과 계정 선택
- 계정 비밀번호
- 사용자에게 보이는 방 코드

## 2. 임시 비밀번호

임시 비밀번호는 계정 비밀번호가 아니라 같은 세션을 찾기 위한 공유 secret이다.

- 브라우저에서 NFKC와 대문자 정규화를 적용하고 영문과 숫자만 사용한다.
- 정확히 6자를 사용한다.
- 입력값은 마스킹하지 않으며 직접 입력하거나 랜덤 생성할 수 있다.
- SHA-256 기반 6자리 내부 세션 key를 만든다.
- 임시 비밀번호 원문은 URL, 브라우저 저장소와 API 요청에 남기지 않는다.
- 방 생성 뒤 대기실에서 원문 대신 파생된 방 key가 포함된 공유 딥링크를 복사할 수 있다.
- 세션이 끝나면 새 임시 비밀번호를 사용한다.

## 3. 인원과 입장 제한

| 상황                               | 규칙                                                          |
| ---------------------------------- | ------------------------------------------------------------- |
| 첫 사용자                          | 혼자 대기실에 입장하며 방장이 된다.                           |
| 시작 전 참가                       | 1~8명이 같은 대기실에 참여한다.                               |
| 참가자 8명                         | 세션 정원이 찬 상태다.                                        |
| 9번째 신규 사용자                  | 접속을 거부한다.                                              |
| 정원 초과 사용자                   | 관전자나 대기열로 자동 전환하지 않는다.                       |
| 기존 사용자의 동일 identity 재접속 | 정원이 찼거나 게임이 진행 중이어도 기존 자리로 복귀한다.      |
| `waiting`에서 빈자리 발생          | 새로운 사용자가 대기실에 참가할 수 있다.                      |
| 방장 시작 뒤 신규 사용자           | 진행 중인 준비·토너먼트에는 참가할 수 없으며 접속을 거부한다. |

서비스 전체에서 동시에 유지하는 활성 room은 최대 20개다. 만료 room을 정리한 뒤에도 20개가
유효하면 새 room 생성은 capacity 오류로 거부한다. 이 제한은 room 하나의 참가자 최대 8명과 별개다.

신규 사용자는 `waiting` 대기실에만 참가할 수 있다. 방장 시작 뒤에는 준비 중이어도 참가자 명단을
잠그며, 기존 참가자의 동일 identity 재접속만 허용한다. 준비가 참가자 부족으로 취소돼 다시
`waiting`이 되면 대기실을 다시 열고 빈자리에 신규 사용자를 받을 수 있다.

## 4. 동일 사용자 판정

동일 사용자는 닉네임이나 임시 비밀번호가 아니라 같은 브라우저 프로필의 `localStorage`에
저장된 `playerId + sessionId` 조합으로 판별한다. 저장 항목은 계정별 identity, 현재 방 코드와
서버가 준 만료 시각이며 임시 비밀번호 원문과 ID token은 저장하지 않는다.

| 상황                                                 | 판정        |
| ---------------------------------------------------- | ----------- |
| 같은 브라우저 프로필에서 새로고침                    | 동일 사용자 |
| 저장 방 만료 전 같은 프로필에서 브라우저 종료·재실행 | 동일 사용자 |
| 같은 브라우저 프로필의 다른 일반 탭                  | 동일 사용자 |
| 시크릿 탭                                            | 신규 사용자 |
| 다른 브라우저 프로필·기기                            | 신규 사용자 |
| 격리된 context에서 같은 닉네임 사용                  | 신규 사용자 |
| 명시적으로 나간 뒤 다시 입장                         | 신규 사용자 |

닉네임은 화면에 보이는 이름이며 사용자 identity가 아니다.

## 5. 연결과 나가기

- Socket 연결이 끊기면 참가자 자리를 60초 동안 유지한다. 이 시간은 열린 페이지의 일시적인
  네트워크 단절을 복구하는 Socket 유예 시간이다.
- 같은 identity가 60초 안에 재연결하면 기존 자리를 복구한다.
- 대기실 참가자가 60초 안에 재연결하지 않으면 자리를 제거한다. 이후에도 방이 `waiting`이고
  빈자리가 있으면 같은 브라우저 프로필에서 저장 identity로 한 번 재입장할 수 있다. 마지막
  참가자의 자리까지 제거돼 빈 대기실이 되어도 방은 즉시 닫지 않는다.
- 탭이나 브라우저 종료는 `/leave`를 호출하지 않으며 `localStorage` identity를 유지한다.
- 명시적으로 나가면 서버 `/leave`를 호출하고 저장 identity를 지운 뒤 입장 화면으로 돌아간다.
- 방장의 연결이 끊겨도 60초 유예 동안에는 방장 권한을 다른 참가자에게 넘기지 않는다.
- 대기실에서 방장이 명시적으로 나가거나 유예 만료로 제거되면 다음 최초 입장자가 방장이 된다.
- shared world에서 한 사용자가 나가도 2명 이상이 남으면 다른 사용자는 계속 플레이한다.
- 진행 중인 경쟁 매치에서 나가 경기 지속 조건을 잃으면 `forfeit`로 처리할 수 있다.

브라우저를 다시 열면 다음 순서로 복구한다.

1. `localStorage`의 개인 진행과 계정별 방 identity를 읽고 로컬 만료 시각을 확인한다.
2. 만료 전이면 REST room snapshot을 조회해 서버 상태를 기준으로 삼는다.
3. 기존 참가자가 남아 있으면 같은 identity로 snapshot을 복원하고 Socket을 다시 구독한다.
4. 대기실 자리만 이미 제거됐다면 같은 identity로 `/join`을 정확히 한 번 호출한다. 이때 ready와
   방장 여부는 현재 대기실 순서로 다시 계산한다.
5. 방이 만료·`closed`됐거나 진행 중 방에서 기존 참가자를 찾을 수 없으면 저장 방 identity를 지우고
   입장 화면으로 돌아간다.

서버 room 보존 시간은 `waiting` 30분, `active` 2시간, `completed`·`closed` 10분이다. 따라서
60초 Socket 유예가 지나도 이 보존 시간과 위 조건 안에서는 브라우저 종료 후 재개할 수 있다.

## 6. 공유 상태

같은 세션 사용자에게 공유하는 값은 다음과 같다.

- 서버가 승인한 닉네임
- 현재 월드 위치
- 바라보는 방향
- 방장, 준비, 참가·나가기와 연결 상태
- 대표 포켓몬의 종·레벨·HP, 파티 수와 파티 갱신 시각
- 챔피언십 참가자·대진·매치 결과·라운드 점수·누적 순위

## 7. 개인 상태

다음 값은 각 사용자의 개인 진행으로 유지한다.

- PC 박스와 파티의 전체 구성
- 포켓몬의 상세 HP, PP, 상태, 기술과 IV
- 돈과 인벤토리
- 야생 조우와 포획
- 개인 전투와 성장 보상

다른 사용자는 공개 파티 요약만 볼 수 있고 전체 파티·기술·IV·재화·인벤토리는 볼 수 없다. 한
사용자가 야생전에 들어가도 다른 사용자는 월드에서 계속 움직일 수 있다.

챔피언십에서는 준비 종료 시점의 파티 복사본만 frozen party로 서버가 관리한다. 경쟁 매치에서
발생한 피해와 PP 소비는 개인 월드 파티에 반영하지 않는다.

## 8. 대기실과 챔피언십

멀티플레이 세션은 shared world의 접속 단위다. 챔피언십은 같은 세션 참가자가 3라운드 동안
경쟁하는 게임 진행 단위다.

`waiting`에서는 월드 이동과 상호작용을 막고 대기실을 표시한다. 각 참가자의 현재 파티는
서버에 자동 동기화하지만 ready는 사용자가 직접 선택한다.

AI 닉네임은 골드·실버의 일반 트레이너 이름 18개 중 하나를 무작위로 사용하며, 같은 방에서는
중복하지 않는다. AI 여부는 닉네임이 아니라 대기실의 AI 배지로 구분한다.

방장은 현재 대기실 참가자를 입장 시각과 player ID 순서로 정렬했을 때 첫 번째 사용자다.
방장 시작은 다음 조건을 모두 만족해야 한다.

1. 참가자가 1~8명이다.
2. 서버가 모든 참가자를 `connected`로 판정한다. disconnect-pending 참가자는 60초 유예 동안
   기존 자리와 시작 자격을 유지한다.
3. 모든 참가자의 현재 파티가 서버에 동기화됐다.
4. 모든 참가자가 ready를 선택했다.

ready만으로 준비 타이머를 자동 시작하지 않는다. 방장이 시작하면 서버는 현재 사람과 수동으로
추가한 AI를 합산해 1~~3명은 4명까지, 4~~7명은 8명까지 AI를 자동 추가한다. 8명이면 추가하지
않는다. 자동 AI 추가와 1라운드 시작은 하나의 Redis room 변경으로 확정되며, 시작 snapshot부터
AI의 참가자와 starter party가 함께 존재한다.

서버는 같은 시작 시각을 기준으로 1라운드 준비 종료 시각을 정확히 3분 뒤로 정하고 모든
참가자에게 같은 상태를 전파한다. 이후 신규 사용자는 참가할 수 없고 기존 참가자의 재접속만
허용한다.

방장은 혼자여도 파티 동기화와 ready를 마치면 시작할 수 있으며, 이 경우 AI 세 명이 자동
참가해 4인 준비를 시작한다. 준비 종료 시 참가자가 2명 미만이면 대진을 만들지 않고
`waiting`으로 돌아간다. 이때 남은 참가자의 ready를 해제하고 대기실을 다시 열며, 전원이 다시
준비한 뒤 방장이 현재 라운드의 새 3분 준비를 시작한다.
정상적으로 1·2라운드가 끝났고 참가자가 2명 이상이면 다음 라운드의 3분 준비는 별도 ready 없이
자동 시작한다.

화면에는 현재 게임 라운드와 준비 종료까지 남은 시간을 표시한다. 이후의
3라운드·준비 3분·토너먼트·남은 체력 비율 점수·최종 우승 규칙은
[3라운드 챔피언십](./three-round-championship.md)에 고정돼 있다.

## 9. AI 참가자

- 방장은 `waiting` 대기실에서 정원 8명 안에서 AI를 추가하거나 제거할 수 있다.
- 방장이 시작할 때 현재 사람과 수동 AI가 1~~3명이면 4명까지, 4~~7명이면 8명까지 AI를 자동
  추가한다. 수동 AI도 현재 인원에 포함하며 8명이면 자동 추가하지 않는다.
- AI는 서버가 관리하며 무작위 스타터 한 마리로 시작한다. 별도 로그인·브라우저 세션·DB 전적은
  만들지 않고 room TTL과 함께 Redis에서 제거한다.
- 자동 추가된 AI는 방 시작 snapshot부터 참가자로 존재한다. AI는 준비 단계에서 월드를 이동하고
  풀숲 안에서만 주기적으로 사냥·포획한다. 포획 판정과 파티 제한은
  플레이어와 같은 규칙을 사용하며 현재 행동은 월드 이름표에 표시한다.
- AI는 ready를 누르지 않아도 준비된 참가자로 취급한다. 사람 참가자만 자신의 ready를 직접
  선택한다.
- 챔피언십에서 AI는 일반 참가자와 같은 frozen party, 서버 전투 판정, 제한 시간과 점수 규칙을
  사용한다. 행동은 서버가 자동 제출하며 사용 가능한 공격 중 기대 피해가 가장 큰 기술을 고르고,
  기절하면 남은 체력 비율이 가장 높은 포켓몬으로 교체한다.
- 난이도 선택, LLM 판단, AI 전적 영구 저장은 제공하지 않는다.
