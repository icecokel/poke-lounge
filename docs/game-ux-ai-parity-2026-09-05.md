# 게임 UX·AI 조건 일치 개선

브랜치: `feature/game-ui-ai-parity`

## 변경

- 모바일: 전투 메시지 영역과 조작 영역을 고정 분리. 명령·기술 선택은 같은 2×2 배치로 유지하고, 처리 중에는 자리를 바꾸지 않고 비활성화한다. 일반 메시지는 자동 진행하며 결과처럼 확인이 필요한 경우만 확인 버튼을 남겼다. 설정·도움말·뒤로 터치 타깃은 최소 44px.
- 전투: 상단에 지속적인 관전 표식과 양쪽 트레이너 이름을 표시한다. 모바일 관전에는 행동 버튼을 노출하지 않는다. 트레이너 포켓몬은 볼 투척·빛·확대 등장(640ms), 야생 상대는 볼 연출 제외. 파티 슬롯이 바뀌면 같은 종이라도 다시 등장한다.
- 회복: HP 증가 보간, 초록 발광·상승 입자, HP 패널 강조. 간호사 회복 연출과 대기 시간을 1,200ms로 일치시켰다. 모션 감소 설정을 존중한다.
- 현재 게임: HUD 순위·점수의 원본을 현재 토너먼트 누적 점수로 통일하고 동점 순위를 처리한다. 문구도 ‘현재 게임’으로 명시한다.
- Storybook: 실제 배틀 화면과 모바일 조작부를 함께 보여주고 메시지·대기·결과·관전·회복·볼 등장 상태를 추가했다. 존재하지 않던 스토리용 개별 이미지 경로를 실제 게임의 스프라이트 시트로 교체했다.

## AI 원인과 수정

기존 서버는 절대 경과 시간과 개체별 오프셋으로 경로 좌표를 계산하고, 주기적으로 포켓몬을 자동 추가했다. 실제 이동 거리·충돌·조우·전투·소모 자원을 거치지 않는 별도 규칙이었다.

이제 플레이어가 쓰던 이동·맵·조우·야생 전투·포획·경험치·레벨업·회복 로직을 `packages/poke-lounge-battle/src/adventure`로 옮겨 양쪽에서 공유한다. 웹의 기존 import 경로는 재내보내기로 유지했다.

- 속도 104px/s, 서버 tick 최대 250ms(26px), 실제 충돌 검사·풀숲 타일 이동 조우. 사람이 먼저 움직여야 AI가 시작하던 조건 제거.
- 같은 ROM 데이터, IV 범위, 시작 레벨·볼 10개·소지금 0, HP·PP·상태·포획 확률·파티/박스 제한·성장 규칙 사용.
- 이동 → 실제 야생 전투 → 체력/PP 조건에 따른 간호사 이동·회복. 일정 시간 뒤 자동 포획하거나 준비 라운드마다 무료 회복하지 않는다.
- PvP 진입 시에는 플레이어의 `COMPETITIVE_ASSIGNMENT`와 동일하게 회복하고, PvP 피해는 월드 파티에 역으로 기록하지 않는다.
- 기절·강제 교체 중에는 출전용 파티 전송만 보류하고 실제 시뮬레이션은 계속 진행한다. 잘못된 파티 상태로 방 전체 tick이 중단되던 문제를 회귀 테스트로 고정했다.
- 실제 ROM API가 실패하거나 데이터가 비어 있거나 무결하지 않으면 오류를 유지하고 재시도한다. 정적 샘플로 우회하지 않는다. Docker worker는 API가 healthy인 뒤 시작한다.
- 이동 상태는 Redis의 별도 AI 상태로 보관한다. 이동만으로 방 revision을 올리지 않으며, 파티 갱신 충돌 시 미승인 좌표·파티를 공개하지 않는다.

## 검증

- 공유 로직: Jest 83개 통과(지연 tick 이동 한도, 충돌, 풀숲 조우, 실제 HP/PP, 볼 소모, 기절 후 회복, 10분 준비 시뮬레이션 포함).
- API: Jest 387개 통과(파티 CAS 충돌, 기절 중 상태 저장, ROM 오류/빈 응답/복구 포함).
- 웹: unit 339개 통과. 웹 typecheck, 웹/API lint, 웹/API/Storybook production build 통과.
- 신규 API 경로 mock-fallback 검사: 검출 없음. Storybook은 큰 청크 경고만 남는다.
- 브라우저: 전용 로컬 테스트 DB·Redis와 실제 API/worker 사용. Chromium Mobile Web 390×844, touch=5 및 음소거 확인. 배포 빌드에서 스타일시트 3개 로드, 가로 넘침 없음, 런타임 errors 없음.
- 실제 준비 필드: AI의 이동/사냥/회복 표시와 좌표 변화 확인. 900ms/56 프레임 표본에서 최대 프레임 이동 4.21px, 보행 스프라이트 프레임 6종 관찰.
- 실제 전투: production build에서 양쪽 실제 닉네임 표시, 기술 입력 `session-actions` POST 201, 추가 ‘다음’ 입력 없이 명령으로 복귀 확인. Storybook에서 트레이너 양쪽 볼 연출 2개/야생에서는 아군만 1개, 회복 입자 4개, 관전 행동 버튼 제거, 결과 확인 버튼 1개 확인.
- production build의 패배 결과를 확인 버튼 1회로 종료하고 다음 준비 라운드로 복귀했다. HUD는 ‘라운드 2/3, 현재 게임 랭크 2 · 점수 0’으로 갱신됐다.
- 정리: 테스트 방 각각 UI 퇴장 POST 201을 확인했다. 두 방 모두 `closed`, 연결된 사람 0명, 월드/AI 상태 키 없음까지 확인한 뒤 전용 브라우저와 서버를 종료했다. 재현용 로컬 테스트 DB는 유지했다.
- 개발 중 HMR에서 동적 CSS가 빠지는 현상이 있어 개발 세션과 분리된 production build로 재확인했다. 배포 빌드의 화면은 정상 표시했다.

이 검증은 변경 범위에 대한 회귀/브라우저 점검이며, 3라운드 최종 우승·전원 순위 수렴까지의 전체 멀티플레이 사이클 통과를 의미하지 않는다. 실제 iPhone/iPad Safari 실기기 점검도 별도로 필요하다.
