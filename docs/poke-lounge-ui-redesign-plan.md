# Poke Lounge UI/HUD redesign plan

## 목표

포켓몬스터 하트골드/소울실버의 명확한 픽셀 UI 문법을 참고해 Poke Lounge의 UI와 HUD 전체를 리디자인한다. 기존 게임의 이동, 상호작용, 전투, 포획, 파티 교체, 아이템, 상점, PC, 멀티플레이, 저장 기능과 기존 에셋은 그대로 유지한다.

레퍼런스는 [`docs/references/heartgold-ui`](./references/heartgold-ui/README.md)에 정리되어 있다.

## 디자인 원칙

- **Visual thesis:** 밝은 아이보리 패널, 짙은 픽셀 외곽선, 낮은 입체 그림자, 상황별 포인트 컬러로 작은 영역에서도 상태가 즉시 읽히게 한다.
- **Content plan:** 월드에서는 플레이 공간을 우선하고 HUD를 가장자리에 둔다. 전투에서는 포켓몬과 HP를 상단에, 메시지와 행동 선택을 하단에 둔다. 전체 화면 메뉴는 한 화면에 한 가지 작업만 맡긴다.
- **Interaction thesis:** 선택 상태는 커서와 명도 차이로 표현하고, 버튼은 짧은 눌림 피드백을 준다. 패널은 120~180ms 안에 열고 닫으며, 메시지 진행 표시는 짧게 점멸시킨다.

## 변경하지 않는 것

- 게임 규칙, 상태 스토어, 서버 계약, 저장 데이터 형식
- 키보드, 가상 게임패드, 터치 입력의 액션 매핑
- 월드 타일, 캐릭터, 포켓몬, 전투 배경 등 현재 런타임 에셋
- 테스트와 브라우저 자동화가 참조하는 `data-poke-lounge-*` 속성
- 데스크톱 게임 프레임의 `4:3` 비율

## 공통 컴포넌트

기존 `Button`, `Dialog`, `AlertDialog`의 접근성 동작은 유지하고 게임 전용 시각 컴포넌트를 얇게 조합한다.

| 컴포넌트      | 역할                                        | 사용 위치                              |
| ------------- | ------------------------------------------- | -------------------------------------- |
| `PixelPanel`  | 공통 프레임, 테두리, 그림자, 색상 변형      | 메뉴, 상세 화면, 설정, 알림            |
| `PixelButton` | 선택, 눌림, 비활성, 위험 상태               | 전투 명령, 메뉴 행동, 설정             |
| `HealthBar`   | HP 비율과 정상/주의/위험 색상               | 월드 파티, 상세, 전투                  |
| `PokemonSlot` | 스프라이트, 이름, 레벨, HP, 상태, 선택 표시 | 월드 HUD, 전투 교체, 모바일, 설정 파티 |
| `MessageBox`  | 메시지, 진행 커서, 잠금 상태                | 월드 대화, 전투 메시지, 시스템 안내    |
| `StatusBadge` | 연결, 저장, 상태 이상 등 짧은 상태          | 상태 레일, 포켓몬 상태                 |

공통 색상, 외곽선, 그림자, 간격, 글자 크기와 모션은 게임 프레임의 CSS 변수로 관리한다. 별도 테마 런타임이나 새 UI 라이브러리는 추가하지 않는다.

## 화면별 적용 범위

| 영역        | 현재 구현                                | 리디자인 내용                                                    |
| ----------- | ---------------------------------------- | ---------------------------------------------------------------- |
| 월드 HUD    | `WorldHud`, `PartyHud`, 통화/랭크/라운드 | 가장자리 정보판, 하트골드식 6개 파티 슬롯, HP/상태 표시          |
| 월드 메뉴   | 인벤토리, 상점, PC, 주사위, 도움말       | 공통 패널과 리스트, 명확한 선택 커서, 공통 뒤로가기              |
| 포켓몬 상세 | `PokemonStatusPanel`                     | 스프라이트/기본 정보와 HP·EXP·기술 영역 분리                     |
| 월드 메시지 | 안내, 상호작용, 간호사, 토너먼트         | 상단 알림과 하단 대화창을 용도별로 분리                          |
| 전투 HUD    | `BattleHpPanel`, 메시지, 대기            | 하트골드식 좌우 상태판, HP 단계 색상, 하단 메시지창              |
| 전투 행동   | 명령, 기술, 파티, 가방, 기술 교체        | 2×2 명령, 타입색 기술 목록, 2×3 파티 슬롯, 아이템 목록           |
| 시작 UI     | 방 입장, 혼자 플레이, 스타터 선택, 로비  | 게임 메뉴형 내비게이션과 일관된 선택 상태                        |
| 시스템 UI   | 로딩, 오류, 저장 충돌, 설정, 결과        | 공통 프레임과 버튼을 사용하되 오류/위험 색상 유지                |
| 모바일      | 월드 컨트롤, 모든 메뉴, 전투 덱          | 데스크톱과 같은 컴포넌트 문법을 사용하고 배치만 터치 화면에 맞춤 |

## 구현 단계

### 현재 진행 상태

- [x] 하트골드 UI/HUD 레퍼런스와 컬러 팔레트 정의
- [x] 공통 `PixelPanel`, `PixelButton`, `HealthBar`, `PokemonSlot`, `MessageBox`, `StatusBadge` 구현
- [x] 월드 통화·랭크·라운드와 2×3 파티 HUD, 포켓몬 상세에 1차 적용
- [x] 전투 HP 패널, 메시지창, 명령 버튼에 1차 적용
- [ ] 월드 전체 메뉴와 알림 적용
- [ ] 전투 기술·파티·가방 화면 적용
- [ ] 시작·로비·설정·결과·모바일 적용
- [ ] 전체 플레이 회귀 검증

### 1. 기준 화면과 UI 계약 고정

- 데스크톱과 모바일에서 시작, 월드, 월드 메뉴, 전투 각 상태의 기준 스크린샷을 남긴다.
- 모든 버튼, 상태, 키보드/터치 입력과 `data-poke-lounge-*` 셀렉터를 목록화한다.
- 현재 보이는 UI 크기를 `100%`로 매핑하고 `150%` 확대 옵션을 제공하되 게임 월드 배율과 UI 배율은 분리한다.

완료 조건: 리디자인 전후 기능 회귀를 비교할 수 있는 기준 화면과 조작 목록이 있다.

### 2. 디자인 토큰과 공통 컴포넌트

- 게임 프레임에 색상, 외곽선, 그림자, 간격, 글자 크기, 모션 CSS 변수를 추가한다.
- `PixelPanel`, `PixelButton`, `HealthBar`, `PokemonSlot`, `MessageBox`, `StatusBadge`를 구현한다.
- 포커스, 키보드 조작, `aria-*`, 비활성 상태를 포함한다.

완료 조건: 실제 데이터로 공통 컴포넌트의 정상, 선택, 비활성, 위험 상태를 확인한다.

### 3. 월드 HUD와 월드 메뉴

- 통화, 랭크, 라운드를 상단 가장자리 정보판으로 통합한다.
- 파티 HUD를 하트골드 비율의 6개 슬롯으로 교체하고 HP와 상태 이상을 표시한다.
- 포켓몬 상세, 인벤토리, 상점, PC, 주사위, 도움말에 공통 패널을 적용한다.
- 상호작용 안내, 지역/토너먼트 알림, 대화 메시지의 시각 우선순위를 정리한다.

완료 조건: 이동과 상호작용을 막지 않고 모든 월드 기능을 마우스, 키보드, 터치로 사용할 수 있다.

### 4. 전투 HUD와 전투 메뉴

- 적/아군 상태판, HP 바, 상태 이상, 전투 메시지를 리디자인한다.
- 싸운다/가방/포켓몬/도망 명령과 기술, 아이템, 파티 교체, 기술 교체 화면을 공통 컴포넌트로 교체한다.
- 포획, 진화, 등장 연출은 유지하고 새 HUD와 겹침만 조정한다.
- 로컬 전투와 서버 권위 전투가 같은 표시 컴포넌트를 사용하도록 유지한다.

완료 조건: 일반 공격, 기술 선택, 가방, 교체, 강제 교체, 포획, 도망, 승패, 진화 흐름이 모두 동작한다.

### 5. 시작·로비·설정·결과 UI와 모바일 통합

- 방 입장, 혼자 플레이, 스타터 선택, 멀티 로비, 로딩/오류, 설정, 저장 충돌, 결과 화면에 동일한 디자인 문법을 적용한다.
- 1,400줄 이상인 `mobile-game-shell.tsx`를 월드 컨트롤, 월드 메뉴, 전투 덱, 설정 화면 단위로 분리한다.
- 데스크톱과 모바일이 `PokemonSlot`, `HealthBar`, `MessageBox`를 공유하고 CSS 배치만 분리하도록 정리한다.
- 안전 영역, 가로/세로 전환, 작은 화면의 스크롤과 터치 영역을 확인한다.

완료 조건: 데스크톱과 모바일에서 같은 상태가 같은 색상, 프레임, 선택 규칙으로 표시된다.

### 6. 회귀 검증과 정리

- 포맷, lint, 웹 단위 테스트, 프로덕션 빌드를 통과시킨다.
- 로컬 브라우저에서 `새 게임 → 스타터 → 이동/상호작용 → 전투 → 기술/가방/교체/포획 → 저장/설정/종료`를 플레이 테스트한다.
- 멀티플레이 방 입장과 로비, 연결/저장 상태 표시를 확인한다.
- 데스크톱 `100%`/`150%`, 모바일 세로/가로 화면을 비교한다.
- 더 이상 사용하지 않는 기존 스타일만 제거한다.

검증 명령:

```bash
pnpm format:check
pnpm lint:web
pnpm test:web
pnpm build:web
```

완료 조건: 기능 회귀 없이 자동 검사와 핵심 플레이 사이클을 통과하고, 기존 기능을 대체한 죽은 UI 스타일이 남지 않는다.

## 전체 완료 기준

- UI와 HUD의 모든 화면이 하트골드 기반의 하나의 시각 시스템을 사용한다.
- 모든 반복 UI가 컴포넌트화되고 데스크톱/모바일에서 공유된다.
- 현재 UI 크기가 `100%`이며 `150%` 옵션이 게임 월드가 아니라 UI 묶음에만 적용된다.
- 기존 게임 기능과 에셋이 손실되지 않는다.
- 키보드, 마우스, 터치, 스크린리더 접근성이 유지된다.
- 자동 검사와 브라우저 플레이 테스트를 통과한다.
