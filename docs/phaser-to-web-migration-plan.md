# Poke Lounge Phaser 제거 및 Web UI 전환 계획

- 작성일: 2026-08-30
- 작업 브랜치: `migration/phaser-to-web`
- 상태: 완료

## 1. 목적

Poke Lounge의 Phaser 기반 화면 런타임을 제거하고 기존 Next.js 15, React 19, DOM,
CSS만으로 게임 흐름을 제공한다. 게임 규칙, 저장 데이터, API, 멀티플레이 프로토콜과
에셋은 최대한 유지하며 화면 렌더링 계층만 교체한다.

이 작업에서 다른 게임 엔진, Canvas 렌더러, 전역 상태 라이브러리 또는 애니메이션
라이브러리는 추가하지 않는다.

## 2. 기본 제품 결정

기본안은 Phaser 월드를 DOM으로 그대로 복제하지 않고 **Web 허브 화면**으로 바꾸는 것이다.

- 자유 보행, 타일 충돌, 카메라, 가상 조이스틱은 제거한다.
- 마을의 NPC 기능은 허브의 메뉴와 패널로 옮긴다.
- 야생 조우는 지역 카드에서 탐험을 선택하는 방식으로 진입한다.
- 배틀, 포획, 성장, 파티, PC, 상점, 회복, 솔로 도전, 멀티플레이와 토너먼트는 유지한다.
- 기존 이미지, 배틀 배경, 포켓몬 스프라이트와 오디오는 재사용한다.

보행 월드 자체가 제품 요구사항이라면 이 계획의 4단계를 DOM 타일 월드 구현으로 바꿔야
한다. 이 경우 Tiled JSON 파싱, 충돌, 키보드/터치 이동과 위치 동기화를 다시 구현해야 하므로
별도 범위로 산정한다. 다른 게임 엔진을 도입하는 방식은 선택지에 포함하지 않는다.

### 현재 진행 현황

- Phaser와 무관한 저장 구독, 룸 생명주기와 전투 데이터 런타임을 분리했다.
- 기본 Poke Lounge 경로를 Web 런타임으로 전환하고 임시 `?renderer=web` 분기를 삭제했다.
- 진입, 스타터, 로비, 허브, 야생 전투와 솔로 도전 DOM UI를 연결했다.
- 허브의 탐험, 파티, 가방, 상점, PC, 회복과 Web 전투의 기술, 도구, 교체, 포획, 보상,
  성장 흐름을 연결했다.
- 데스크톱 핵심 흐름과 390×844 모바일 화면을 실제 브라우저에서 확인했다.
- Phaser 코드·의존성·Canvas 전용 경로를 삭제했다.
- 포맷, 전체 린트, Web 타입 검사, 배틀 63개·Web 265개·API 418개 단위 테스트와 전체
  프로덕션 빌드가 통과했다.
- 32개 일반·모바일 DOM E2E, 로컬 테스트 모드, 격리 PostgreSQL·Redis를 사용한 2인 공개
  로비와 5인 토너먼트 통합 E2E가 모두 통과했다.

## 3. 마이그레이션 전 구조 점검

Phaser를 직접 참조하는 코드는 아래 10개 파일, 약 11,610줄에 집중되어 있다.

- `runtime/game/createPokeLoungeGame.ts`
- `runtime/game/scenes/BattleScene.ts`
- `runtime/game/scenes/BootScene.ts`
- `runtime/game/scenes/WorldScene.ts`
- `runtime/game/scenes/world-scene-encounters.ts`
- `runtime/game/scenes/world-scene-hud.ts`
- `runtime/game/scenes/world-scene-interactions.ts`
- `runtime/game/ui/gameTextStyle.ts`
- `runtime/game/world/tall-grass.ts`
- `runtime/game/world/tall-grass.spec.ts`

현재 `poke-lounge-game.tsx`가 인증, 저장, 설정, 전체 화면, 모바일 외곽 UI를 맡고 Phaser는
`runtime/game-page.ts`와 `gamePageStartup.ts`를 거쳐 `#game-root`에 마운트된다.

### 그대로 재사용할 영역

| 영역          | 재사용 대상                                                           |
| ------------- | --------------------------------------------------------------------- |
| 상태          | `GameStateStore`와 현재 저장 상태 모델                                |
| 전투          | `runtime/game/battle/*`의 전투 규칙, 보상, 포획, 진화, 파티 선택 로직 |
| 네트워크      | `MultiplayerRoom`, WebRTC/서버/로컬 룸 구현과 메시지 타입             |
| 서버          | API, Socket.IO, Redis, 인증, 저장, 순위와 서버 권위 전투              |
| 데이터        | 포켓몬, 기술, 상점, 지역, 배틀 배경과 에셋 카탈로그                   |
| 브라우저 기능 | 현재 Audio API 기반 오디오와 자동 저장                                |

### 교체하거나 제거할 영역

| 현재 구현                  | 변경                                             |
| -------------------------- | ------------------------------------------------ |
| Phaser Game/Scene 생명주기 | React 컴포넌트와 작은 TypeScript 런타임 컨트롤러 |
| Canvas/WebGL 렌더링        | 시맨틱 DOM, CSS Grid/Flex, CSS 애니메이션        |
| Phaser 입력/물리/카메라    | 허브 버튼과 패널 기반 이동 없는 탐색             |
| Scene 내부 HUD/모달        | React 화면과 대화상자                            |
| Canvas 중심 E2E 검사       | role, label, text, test id 기반 DOM 검사         |
| Phaser 패키지와 Canvas CSS | 최종 전환 후 삭제                                |

## 4. 목표 구조

```text
Next.js page
  -> PokeLoungeGame (인증·저장·설정·화면 전환)
    -> Web Runtime (입장·룸·게임 생명주기와 사용자 액션)
      -> GameStateStore
      -> MultiplayerRoom
      -> 기존 API / Socket.IO / WebRTC
```

- 기존 `GameStateStore.subscribe()`를 React의 `useSyncExternalStore()`에 바로 연결한다.
- 화면 상태는 로딩, 스타터 선택, 허브, 전투, 로비, 결과 정도의 단순한 값으로 관리한다.
- 런타임 컨트롤러는 룸 연결과 정리 책임만 가진다.
- 애니메이션은 CSS transition/keyframes를 우선 사용한다.
- 기존 공용 버튼, 대화상자와 스타일 유틸리티를 재사용한다.
- 한 번만 쓰는 추상화, 렌더러 인터페이스와 신규 상태 관리 계층은 만들지 않는다.

## 5. 구현 단계

### 0단계: 기준 동작 고정

1. 현재 로컬, 모바일, 2인, 5인 테스트 시나리오를 기준선으로 기록한다.
2. Phaser E2E 컨트롤러에서 화면과 무관한 액션/상태 스냅샷을 목록화한다.
3. Web 허브 전환으로 삭제되는 보행 동작과 유지되는 게임 기능을 확정한다.
4. 이 단계에서는 API, 데이터베이스와 네트워크 메시지를 변경하지 않는다.

완료 조건: 기존 기능을 `유지`, `Web 방식으로 변경`, `제거` 중 하나로 빠짐없이 분류한다.

### 1단계: 렌더러와 런타임 분리

1. `gamePageStartup.ts`에서 인증 후 입장, 스타터 선택, 룸 연결, 정리 로직을 Phaser 생성과
   분리한다.
2. React가 구독할 `useSyncExternalStore()` 훅을 추가한다.
3. 기존 `createPokeLoungeGame.ts`의 E2E 상태/액션 중 화면과 무관한 부분을 새 런타임으로
   옮긴다.
4. Phaser 경로는 그대로 실행되게 유지해 분리 작업의 회귀를 먼저 확인한다.

완료 조건: 현재 Phaser 화면이 동일하게 동작하면서 입장과 룸 생명주기에 Phaser 타입이
남지 않는다.

### 2단계: 진입·스타터·로비를 React로 전환

1. 로딩, 오류, 닉네임, 스타터 선택과 대기실을 React 화면으로 바꾼다.
2. `gamePageStartup.ts`가 직접 만드는 DOM을 제거하고 React 상태로 표현한다.
3. 키보드 포커스, label, 오류 안내와 모바일 터치 영역을 함께 검증한다.
4. 마이그레이션 브랜치에서만 임시 쿼리로 Web 화면을 열어 검증하고 최종 전환 때 쿼리를
   삭제한다.

완료 조건: 로컬 테스트 모드와 공개/비공개 로비가 Phaser 없이 입장 단계까지 동작한다.

### 3단계: 배틀 화면 전환

1. 전투 상태를 구독하는 React 배틀 화면을 만든다.
2. 기존 순수 전투 로직과 서버 권위 결과를 그대로 사용하고 표시와 입력만 교체한다.
3. 기술 선택, 교체, 도구, 도망, 포획, 진화, 보상과 최종 결과를 순서대로 연결한다.
4. CSS로 체력 변화와 공격 피드백만 구현하고 Scene tween은 재현하지 않는다.
5. 로컬 야생 전투, 솔로 도전, 멀티플레이 전투 순으로 검증한다.

완료 조건: 같은 입력에 기존 규칙과 동일한 결과가 나오고 새 화면에서 모든 전투 종료
경로가 정상 수렴한다.

### 4단계: 월드를 Web 허브로 전환

1. 기존 월드 NPC 기능을 허브의 파티, PC, 상점, 회복, 탐험, 솔로 도전, 멀티플레이
   메뉴로 연결한다.
2. 야생 조우는 지역 선택 후 탐험 액션으로 시작한다.
3. 현재 월드 HUD의 인벤토리, 목표, 토너먼트 상태와 알림을 React 패널로 옮긴다.
4. 월드 좌표 전송은 클라이언트에서 중단하되 서버 메시지 계약은 이 마이그레이션에서
   삭제하지 않는다.

완료 조건: 기존 월드에서 접근하던 유지 대상 기능을 모두 허브에서 사용할 수 있다.

### 5단계: 모바일·접근성·오디오 정리

1. 좁은 화면에서 허브와 전투가 가로 스크롤 없이 동작하게 한다.
2. 가상 조이스틱과 Phaser 키 이벤트 브리지를 제거한다.
3. 모든 액션을 키보드와 터치로 사용할 수 있게 하고 모달 포커스를 검증한다.
4. 기존 음소거, 볼륨과 BGM/SFX 생명주기를 새 화면에 연결한다.

완료 조건: 데스크톱과 모바일에서 동일한 기능을 사용할 수 있고 핵심 플로우에 접근성
차단이 없다.

### 6단계: Phaser 제거와 최종 전환

1. 기본 Poke Lounge 경로를 Web 런타임으로 전환한다.
2. 임시 렌더러 선택 쿼리와 Phaser 경로를 삭제한다.
3. Scene, `createPokeLoungeGame.ts`, `runtime/game-page.ts`와 Canvas 전용 코드를 삭제한다.
4. `phaser` 의존성을 제거하고 lockfile을 갱신한다.
5. `#game-root canvas`, `phaser-game-page`, Canvas 마운트 감지 CSS와 문구를 삭제한다.
6. E2E를 DOM 기준으로 전환하되 시드, 액션과 상태 스냅샷은 계속 사용한다.

완료 조건: 소스, 테스트, 의존성, 빌드 산출물에서 Phaser와 Canvas 전용 참조가 0건이다.

## 6. 테스트 계획

각 단계는 해당 범위의 작은 테스트를 먼저 실행하고 단계 종료 시 아래 검사를 수행한다.

```bash
pnpm format:check
pnpm lint
pnpm type:check:web
pnpm test
pnpm build
pnpm e2e:local-test-mode
pnpm e2e:integration
pnpm e2e:five-player
```

브라우저 검증 항목은 다음과 같다.

- 로그인/비로그인 진입, 스타터 선택과 새로고침 복구
- 파티, PC, 상점, 회복, 인벤토리와 저장
- 야생 전투, 포획, 진화, 보상과 솔로 도전
- 공개/비공개 2인 룸, 준비, 재연결과 결과 수렴
- 5인 토너먼트 라운드 진행과 최종 순위
- 모바일 세로/가로, 키보드 포커스, 음소거와 전체 화면

DOM E2E는 화면 문구보다 role과 label을 우선 사용한다. 테스트를 위해 제품 코드에 우회
로직을 추가하지 않고, 기존 E2E 컨트롤러는 시드와 상태 관찰에만 제한한다.

커밋을 나누지 않는다.

## 8. 배포와 롤백

- 이 브랜치는 별도 운영용 기능 플래그 없이 기본 경로를 Web 화면으로 전환한다.
- 전체 검증 후 Phaser 제거까지 한 PR로 병합한다.
- 병합 후 문제가 생기면 PR revert로 이전 Phaser 버전으로 돌아간다.
- 서버의 월드 위치 프로토콜 삭제는 Web 클라이언트 안정화 후 별도 PR에서 판단한다.

## 9. 완료 기준

- 사용자 유지 대상 기능이 React/DOM 화면에서 동작한다.
- 게임 규칙, 저장 포맷, API와 멀티플레이 결과가 기존과 호환된다.
- 데스크톱, 모바일, 로컬, 2인과 5인 핵심 시나리오가 통과한다.
- `phaser` 패키지와 직접 참조가 제거된다.
- Canvas/WebGL과 다른 게임 엔진을 새로 도입하지 않는다.
- 린트, 타입 검사, 단위 테스트, 빌드와 E2E가 통과한다.

## 10. 제외 범위

- 게임 규칙, 점수, 저장 스키마와 서버 권위 판정 재설계
- API/DB/Redis 구조 변경
- 디자인 시스템 전면 개편과 신규 에셋 제작
- DOM 기반 자유 보행 월드 재구현
- Phaser를 대체하는 다른 게임 엔진이나 Canvas 프레임워크 도입
