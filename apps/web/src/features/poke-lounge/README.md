# Poke Lounge 기능 경계

구현 대조: `617a60c` · 2026-09-08 KST.

이 디렉터리의 목적은 **게임 규칙을 바꾸지 않고 UI 수명주기·기기 입력·저장/통신 구현에서 비즈니스 로직을 분리하는 것**이다. 제품 규칙과 라운드 흐름은 저장소 [README](../../../../../README.md)를 따른다.

## 계층

- `domain`: 파티·박스·아이템·구매·지갑·주사위 등 순수 규칙과 불변 상태 변환. React, DOM, 저장소 구현, HTTP에 의존하지 않는다.
- `application`: 준비 완료 조정, 전투 행동 실행·정산·성장 계획, PC 교환, 진행 복원, 대기실 명령. 외부 작업은 좁은 포트로 주입한다.
- `contracts`: 타입과 데이터 계약만 제공한다.
- `presentation`: 도메인/응용 결과를 버튼·메시지·대진표·카운트다운용 읽기 모델로 변환한다. 상태 확정·저장은 맡지 않는다.
- `adapters`: 브라우저 프레임 감지 등 실행 환경 연결부다. 정책 자체를 결정하지 않는다.

React 컴포넌트는 `components/poke-lounge`에 유지한다. CSS, 포커스, 화면 크기, 선택 강조, 애니메이션, 접근성 표시는 UI 책임이다. React 컨테이너/훅은 애플리케이션 기능을 연결할 수 있지만 규칙의 유일한 구현이 되어서는 안 된다.

## 주요 경계

- 준비: 화면은 렌더링·도착 사실을 제공하고, `readiness-coordinator`가 화면별 준비 요청 수명주기를 관리한다. 화면 준비는 두 프레임을 확인하며 최종 실패는 명시적 재시도를 기다린다. `acknowledge-preparation`은 준비가 여전히 필요할 때 revision conflict를 최대 총 8회 시도하고 이전 라운드/폐기된 화면의 응답은 조정자가 무시한다.
- 로컬 전투: UI 입력 → 공통 행동 실행 → 4세대 규칙 → 성장/정산 → 저장 포트 → 화면 연출/복귀 순서다.
- 서버 전투: 로컬 행동 실행과 구분해 명령 전송·서버 확정 상태를 사용한다.
- 파티·인벤토리: 도메인 함수는 입력을 직접 바꾸지 않고 `{ player, changed, result }`를 반환한다. 저장소 연결부가 `changed`일 때 반영·저장·통지하며 기존 호출 순서를 임의로 합치지 않는다.
- 진행 복원: 저장소 접근과 선택 UI를 분리하고 사용자가 결정하기 전에 어느 쪽도 임의로 덮어쓰지 않는다.

## 남아 있는 레거시 결합

`BattleScreenState`의 문자열 메시지 큐와 화면 재생 단계, `battle-scene`, `world-scene`, `game-page-startup`, `server-room`의 일부 수명주기는 아직 기존 구조를 유지한다. 전체 전투 상태가 순수 도메인 이벤트 모델로 전환된 상태는 아니다.

다음 리팩터링도 파일 크기보다 책임 경계를 기준으로 진행한다. 인벤토리 기술 교체, 서버 경기 배정·복구, 전투 이벤트 재생처럼 독립적으로 검증 가능한 기능 단위로 나눈다.

## 검사

`pnpm test:web`는 기능 단위 테스트와 `testing/architecture.test.ts`를 실행한다. 아키텍처 검사는 core 계층에 React/DOM/HTTP 런타임 의존성이 다시 들어오는 것을 막는다. 제품 규칙 검증과 브라우저 회귀는 각 전용 테스트에서 수행한다.
