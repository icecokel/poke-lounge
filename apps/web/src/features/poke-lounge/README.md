# Poke Lounge 기능 경계

게임 규칙을 바꾸지 않고, 화면 수명주기·기기별 입력·저장 구현과 분리하는 점진적 리팩터링이다. 원본 4세대 엔진과 전투 수치, 기존 저장 포맷 및 API 계약은 유지한다.

## 계층

- `domain`: 파티·박스·아이템·구매·지갑·주사위 규칙과 불변 상태 변환. React, DOM, 저장소 구현, HTTP에 의존하지 않는다.
- `application`: 준비 완료 조정, 전투 행동 실행·정산·성장 계획, PC 교환 흐름, 계정 저장 복원, 대기실 명령. 외부 작업은 좁은 인터페이스로 주입한다.
- `contracts`: 타입과 데이터 계약만 제공한다. 기존 라운드·토너먼트 타입은 단계적 이전을 위해 타입 전용으로 참조한다.
- `presentation`: 도메인/응용 결과를 버튼, 메시지, 대진표, 카운트다운에 필요한 읽기 모델로 변환한다. 게임 상태의 확정·저장을 맡지 않는다.
- `adapters`: 브라우저 프레임 감지 등 실행 환경 연결부다. 준비 정책 자체를 결정하지 않는다.

React 컴포넌트는 `components/poke-lounge`에 유지한다. CSS, 포커스, 화면 크기, 선택 강조, 애니메이션, 접근성 표시는 UI 책임이다. 애플리케이션 기능을 호출하는 React 컨테이너/훅은 연결부이며, 규칙의 유일한 구현이 되어서는 안 된다.

## 주요 흐름

준비: 화면 어댑터가 표시/도착 사실을 제공 → `readiness-coordinator`가 두 프레임·세션 키·중복 요청을 관리 → 서버 준비 요청 → 화면이 카운트다운 읽기 모델을 표시한다. 요청 실패는 명시적 재시도로만 재전송하며, 폐기된 화면과 이전 라운드의 늦은 응답을 무시한다.

전투: UI 입력 → 공통 행동 실행 → 기존 4세대 규칙 → 성장 계획/전투 정산 → 저장 포트 → 화면 알림/복귀. 금액 지급과 파티 저장은 애니메이션 컴포넌트가 처리하지 않는다.

파티·인벤토리: 도메인 함수는 `{ player, changed, result }`를 반환하고 입력을 바꾸지 않는다. `game-state-store` 연결부는 `changed`일 때만 저장하고 구독자에게 통지한다. 여러 저장 작업을 하나로 합치거나 기존 통지 순서를 임의로 변경하지 않는다.

계정 복원: 토큰/계정 수명주기와 저장소 접근은 포트로 전달한다. 서버/로컬 진행 충돌은 데이터 결과로 반환하고, 사용자가 선택하기 전에 어느 쪽도 덮어쓰지 않는다.

## 호환성과 남아 있는 이전 작업

기존 경로를 사용하는 게임 코드·테스트를 깨뜨리지 않도록 일부 파일은 재내보내기 어댑터로 유지한다. 테스트를 없애거나 새 구현에 맞춰 기존 게임 규칙의 기대값을 바꾸지 않는다.

현재 공유 `BattleScreenState`의 문자열 메시지 큐와 화면 재생 단계는 레거시 호환 구조다. 이 저장/상태 계약을 의미 이벤트로 교체하는 작업은 별도 마이그레이션이 필요하다. 이번 분리만으로 전체 전투 상태가 순수 도메인 모델로 바뀐 것은 아니다.

`battle-scene`, `world-scene`, `game-page-startup`, `server-room`은 아직 기존 연결부와 연출/통신 수명주기를 유지한다. 그 전체를 새 이름의 거대한 클래스로 옮기지 않는다. 다음 작업은 인벤토리 기술 교체 세션, 서버 전투 배정/복구, 순수 전투 이벤트 재생 등 실제 책임 단위로 진행한다.

## 검사

`pnpm test:web`는 새 기능의 단위 테스트와 `testing/architecture.test.ts`를 함께 실행한다. 아키텍처 테스트는 core의 React/DOM/HTTP 런타임 의존과 계약에 실행 코드를 추가하는 것을 막는다. 기존 브라우저 회귀 시나리오로 중앙 집결, 강제 교체, 진화, 기술 교체, 웹/모바일 가방 및 서버 전투를 확인한다.
