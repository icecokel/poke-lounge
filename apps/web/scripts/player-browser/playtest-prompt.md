# Poke Lounge 플레이어 관점 반복 테스트·버그 수정 프롬프트

기준 변경: 2026-09-12. **우승 조건은 없다. 실제 플레이어의 조작으로 3라운드 최종 결과까지 문제없이 완료하는 것이 핵심이다.**

```text
@poke-lounge-remote-mcp

Poke Lounge를 실제 브라우저에서 플레이하고, 발견한 버그를 수정·검증·커밋한다.

## 목표와 종료 조건

우승·순위·승률은 합격 조건에서 제외한다. 정상적인 패배는 테스트 실패가 아니다.
새 방에서 시작하여 1~3라운드와 최종 결과까지 실제로 플레이한다.
연속 3회 전체 플레이 PASS 또는 총 플레이 테스트 10회 중 먼저 도달하면 종료한다.
버그 발견 즉시 연속 PASS를 0으로 초기화한다.
수정·관련 회귀 검증·커밋 후 새 방에서 다시 플레이하여 PASS하면 1/3이다.
PASS였어도 다음 회차는 처음부터 시작하며 의심 구간을 반복 확인한다.
최대 횟수에 도달해도 발견한 미해결 버그를 무시하거나 PASS로 바꾸지 않는다.

## 한 회차의 범위

새 브라우저·새 방 생성 → 대기실 준비 → 스타터 선택 → 중앙 집결·출발
→ 1라운드 탐험·토너먼트 → 2라운드 탐험·토너먼트
→ 3라운드 탐험·토너먼트 → 최종 순위·점수 확인
→ 방 나가기 확인 → 입장 화면 복귀.

라운드 하나나 전투 한 번을 전체 플레이 한 회로 세지 않는다.
이전 작업의 결과를 소급 PASS하거나 이번 실적에 합산하지 않는다.

## 실제 조작 방식

현재 스크린샷을 이미지 뷰어로 확인 → 화면을 보고 다음 행동 판단
→ 클릭·탭·키보드·드래그로 단일 행동 → 변경 화면 확인을 반복한다.
Playwright는 브라우저와 입력 전달 수단이며 행동은 에이전트가 판단한다.
자동 플레이 루프·전체 spec 결과만으로 직접 플레이 PASS를 선언하지 않는다.
Base64 문자열이나 파일명, 접근성 텍스트만으로 이미지를 봤다고 기록하지 않는다.

게임 API 직접 호출, 게임 스토어·저장소·DB·Redis·E2E getter를 이용한 플레이,
정적 지도·전투 카탈로그 공략, 상태·HP·아이템·결과 주입,
시계 정지·가속·제한시간 변경, 강제 클릭·비활성 버튼 우회를 금지한다.
버그 재현 후 소스 분석·자동 회귀는 별도 단계에서 수행한다.

## 실제 플레이어 관점의 검사

준비·스타터 선택·이동·대화·전투 기술 선택과 실행·확인·다음 라운드 전환·
최종 결과·퇴장이 막히지 않는지 확인한다. 버튼 클릭과 실제 행동 반영은 구분한다.
화면 겹침·잘림, 보이지 않는 필수 버튼, 입력 누락·중복, 잘못된 안내,
메뉴를 연 채 대회 시작, 패배 후 진행, 데이터 유실·중복을 확인한다.
포획·상점·회복·교체는 가능한 상황에서 점검하고 확인한 범위를 기록한다.
포획 성공·구매 횟수나 특정 순위를 채우는 것이 완주의 전제는 아니다.
검사하지 못한 기능을 정상이라고 추정하지 않는다.

## 사전 점검과 안전

현재 브랜치·HEAD·미커밋 변경을 확인하고 다른 작업의 파일은 보존한다.
README.md, .agents/skills/poke-lounge-agent-browser-test/SKILL.md,
apps/web/scripts/player-browser/README.md를 읽는다.
격리된 로컬 프로덕션 Web·실제 API·PostgreSQL·Redis·워커를 사용한다.
게임 시작 전에 캡처 → 이미지 전달·표시 → 단일 UI 입력 경로를 검증한다.
이미지를 실제로 볼 수 없는 상태에서는 게임을 시작하지 않는다.
다른 작업의 서버·브라우저·컨테이너를 종료하거나 환경 파일을 덮어쓰지 않는다.

## 버그 수정

재현 절차·기대/실제·영향·화면·입력 기록을 확보한다.
버그 발견 시 해당 회차는 PASS가 아니며 연속 PASS=0이다.
원인 분석 → 가능한 수정 전 실패 회귀 → 최소 범위 수정
→ 타입·린트·관련 단위/통합/UI 회귀 → 재빌드 → 실제 UI 재검증 → 커밋.
공유 코드의 다른 호출부, 모바일/데스크톱, 정상/실패/경계 경로를 확인해
수정으로 다른 기능이 깨지지 않았는지 검증한다.
검사를 통과하려고 게임 규칙·타이머·AI·확률·보상을 유리하게 바꾸지 않는다.
원인·효과가 확인되지 않으면 수정 완료로 표시하지 않는다.
푸시는 별도로 요청받은 경우에만 수행한다.

## 조작 공백과 도구 오류

게임 시간이 흐를 때 문서 편집·긴 로그 조회를 끼워 넣지 않는다.
오래된 화면은 재관찰하고, 입력 결과가 불명확하면 무조건 재실행하지 않는다.
도구 실행/입력/캡처/전달/표시 오류와 게임 버그를 구분한다.
관찰 없이 서버 기본 행동에 맡긴 구간은 직접 플레이 PASS 근거가 아니다.
시간 초과 자체의 정상 처리를 관찰한 검사는 별도로 기록한다.
외부 장애로 중단하면 횟수를 채웠다고 하지 말고 실제 도달 지점과 장애를 보고한다.
```
