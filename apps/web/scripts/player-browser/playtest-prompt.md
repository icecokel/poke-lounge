# 플레이어 직접 조작 요청 템플릿

현재 기준은 루트 [PLAYER_TESTING.md](../../../../PLAYER_TESTING.md)다. 자동 테스트 실행이나 상태 주입을 허용했던 이전 템플릿은 폐기한다.

```text
@poke-lounge-remote-mcp

지정한 환경을 실제 브라우저에서 플레이어처럼 테스트한다.
현재 화면 확인 → 에이전트가 다음 행동 판단 → 한 번의 클릭/탭/키보드/드래그/스크롤 → 새 화면과 실제 결과 확인을 반복한다.
기본 도구는 agent-browser이고, 로컬 HTTP에서만 기존 player:browser도 사용할 수 있다.
자동 E2E/단위/API/통합 테스트, Storybook, 게임 상태·아이템·HP·결과 주입, 내부 API 호출, 자동 플레이 루프와 임시 어댑터는 만들거나 실행하지 않는다.

새 방부터 1~3라운드 최종 결과와 정상 퇴장까지가 전체 한 회다. 우승은 조건이 아니다.
모든 버튼을 요청받았다면 화면·버튼·상태별 점검표를 작성하고 선택/확정/취소/복귀와 실제 효과를 확인한다.
미검증 버튼·조건이 있으면 전체 PASS/완료로 보고하지 않는다.
반복 검사에서는 연속 3회 PASS 또는 총 30회 시도 중 먼저 도달하면 종료하며 별도 사용자 지정이 있으면 그것을 따른다.

버그 발견 즉시 연속 PASS를 0으로 초기화한다.
화면·입력 증거 확보 → 사후 소스 분석 → 최소 수정 → 빌드/정적 확인 → 동일 UI와 주변 동작을 다시 직접 조작한다.
정적 확인은 테스트 PASS가 아니다. 자동 회귀를 새로 만들지 않는다.
커밋·푸시는 사용자가 허용한 범위에서만 수행한다.

입력·캡처·이미지 전달·도구 차단·제품 오류를 구분한다.
이미지가 없거나 읽을 수 없으면 직접 플레이를 시작하지 않는다.
입력 결과가 불분명하면 자동 재전송하지 않는다. 운영 설정과 게임 시간은 변경하지 않는다.
기록/스크린샷은 docs/와 output/에 보관하고 민감값을 노출하지 않는다.
UI로 퇴장한 뒤 이번에 만든 브라우저만 닫고, 실제 도달 범위·문제·미검증·정리 상태를 보고한다.
```
