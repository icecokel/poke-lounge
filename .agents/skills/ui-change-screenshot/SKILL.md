# UI 변경 후 화면 캡처 제공

사용자가 UI 변경을 요청하면 구현 완료 후 변경된 실제 화면의 캡처 이미지를 최종 채팅 답변에 반드시 제공한다. 사용자가 별도로 캡처를 요청할 필요는 없다.

## 작업과 캡처

- 구현 후 실제 앱을 브라우저나 해당 앱에서 열고, 요청한 변경이 보이는 화면까지 직접 조작한다. 프로젝트의 `AGENTS.md`, 플레이어 테스트 지침과 사용 가능한 브라우저 스킬을 따른다.
- 사용자 요청의 화면 크기나 제공된 참고 이미지에 맞춰 캡처한다. 지정이 없으면 변경을 명확하게 확인할 수 있는 화면 크기를 사용한다.
- 화면 전환, 로딩과 애니메이션이 끝난 뒤 캡처하고 이미지 뷰어로 직접 열어 변경 결과가 보이는지 확인한다. 문제가 보이면 수정 후 다시 캡처한다.
- 선택창, 모달, 메뉴처럼 열어야 보이는 UI를 변경했다면 열린 상태의 캡처를 제공한다. 위치 변경도 함께 요청했다면 위치를 확인할 수 있는 기본 화면도 제공한다.
- 캡처는 허용된 작업공간의 증거 저장 경로에 보관한다. 프로젝트에 `output/` 등 지정 경로와 Git 제외 규칙이 있으면 그대로 따른다.
- 실제 캡처를 사용한다. 참고 이미지, 생성 이미지, 접근성 텍스트나 파일명만으로 구현 결과의 캡처를 대신하지 않는다. 민감한 정보가 보이지 않는 화면을 선택한다.

## 채팅 전달

최종 답변에 변경 내용을 짧게 설명하고 캡처 이미지를 Markdown 이미지 문법으로 첨부한다. 로컬 이미지는 실제 파일의 절대 경로를 사용한다.

```markdown
새로 고침 옆의 언어 아이콘을 누르면 언어 선택창이 열리도록 변경했습니다.

![변경 후 언어 선택창](/absolute/workspace/output/ui-change/language-selector.png)
```

- 캡처 경로의 텍스트나 다운로드 링크만 제공하고 끝내지 않는다. 사용자가 채팅 안에서 이미지를 바로 볼 수 있어야 한다.
- 캡처를 확인한 화면과 실제 조작으로 검증한 동작을 구분하고, 미검증 범위가 있으면 짧게 밝힌다.
- 캡처 도구나 앱 실행이 막히면 기존의 허용된 대안을 사용한다. 해결할 수 없으면 차단 원인과 캡처 미제공 상태를 명시하고, 캡처까지 완료했다고 보고하지 않는다.
- 사용자가 캡처를 원하지 않는다고 명시하면 그 요청을 우선한다.
