# 플레이어 직접 조작

필수 기준은 루트 [PLAYER_TESTING.md](../../../PLAYER_TESTING.md)와 [AGENTS.md](../../../AGENTS.md)다. 이전 버전의 자동 회귀, E2E getter, 테스트 DB 조회 허용 지침은 폐기한다.

## 도구 선택

기본은 기존 `agent-browser`다. 고유 named session을 생성하고 현재 설치 버전의 `agent-browser skills get core --full`을 읽는다. 로컬과 사용자가 지정한 운영 사이트 모두 실제 브라우저로 접근한다. 운영 작업을 로컬 production 빌드로 바꾸지 않는다.

기존 [player:browser](../../../apps/web/scripts/player-browser/README.md)는 로컬 HTTP에서만 사용하는 대안이다. Playwright는 지속적인 브라우저·개별 입력·캡처를 위한 API로만 허용한다. Playwright Test Runner, Jest, 자동 spec, Storybook, 임시 production-player/step/ui 어댑터는 사용하거나 다시 만들지 않는다.

## 직접 조작 순서

현재 화면을 이미지로 열기 → 화면을 보고 다음 행동 판단 → 한 번의 실제 입력 → 새 화면에서 실제 효과 확인을 반복한다. 화면 전환 후에는 새 snapshot/ref를 사용한다. 접근성 텍스트는 보조이며 이미지 확인을 대신하지 않는다.

데스크톱은 기본 1440×900, 모바일 에뮬레이션은 기본 390×844와 터치 입력을 사용한다. 에뮬레이션을 실기기 테스트로 표현하지 않는다. 기존 `scripts/desktop-arrow-hold.mjs`는 개별 방향키 입력 전달에만 사용하며 조작을 자동 선택하지 않는다.

보이는 버튼의 선택/확정/취소/복귀와 실제 상태 변화를 확인한다. 도구 요청 전송만으로 PASS하지 않는다. 상태 주입, 내부 게임 API/스토어/저장소/DB/Redis/getter 조회, 미리 정한 행동 반복, 강제 클릭, 비활성 버튼 우회는 금지한다.

새 방부터 3라운드 최종 결과와 UI 퇴장까지가 전체 한 회다. 우승은 조건이 아니다. 모든 버튼 확인 요청은 미검증 조건이 남으면 미완료다. 반복 횟수·문제 판정·정리는 PLAYER_TESTING.md를 따른다.

실제 버그를 만난 뒤의 소스 분석은 플레이와 분리한다. 수정 재검증도 실제 UI에서 수행한다. 타입·린트·빌드는 별도의 정적/빌드 확인일 뿐 플레이어 테스트가 아니다.

## 장애와 정리

이미지를 볼 수 없거나 명령이 차단되면 그 단계의 장애로 기록한다. 입력 결과가 불분명할 때 재전송하지 않는다. 보안 차단을 다른 명령·API로 우회하지 않는다. 게임 시간과 운영 설정은 변경하지 않는다. 별도로 요청된 로컬 시간 완화는 격리된 로컬에만 적용하고 보고한다.

자신이 만든 방에서 UI 퇴장 후 자신이 연 세션만 종료한다. 다른 작업의 서버/브라우저/컨테이너는 건드리지 않는다. 증거는 `output/`, 실행 원장은 `docs/`에 남기고 두 경로의 Git 제외를 유지한다. 비밀번호·방 코드·세션 식별자를 노출하지 않는다.
